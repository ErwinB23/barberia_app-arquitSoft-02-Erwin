# Atributos de calidad

| ID | Atributo | Escenario de calidad | Criterio propuesto |
|---|---|---|---|
| AC01 | Seguridad | Un usuario intenta consultar una reserva ajena o confirmar un pago sin estar autorizado. | El servidor rechaza el acceso, no entrega datos privados ni modifica el pago. Valida identidad, recurso, barbería y membresía activa; el barbero debe estar asignado a la cita y el administrador autorizado debe pertenecer al establecimiento. La comunicación usa HTTPS. |
| AC02 | Aislamiento entre barberías | Un administrador de la barbería A intenta modificar datos o imágenes de B, o un cliente intenta reseñar una atención ajena. | Las políticas y relaciones por barbería y usuario impiden operaciones sobre recursos ajenos aunque se cambien identificadores en la solicitud; la consulta pública de información publicada no concede acceso de escritura. |
| AC03 | Integridad transaccional | Dos clientes intentan reservar un mismo intervalo o dos personas intentan confirmar el mismo pago al mismo tiempo. | Como máximo se confirma una reserva por intervalo incompatible y un pago se marca como recibido una sola vez; no quedan reservas, pagos ni registros de confirmación parcialmente creados. |
| AC04 | Rendimiento | Clientes consultan catálogo, disponibilidad y reservas durante horas de alta demanda. | Objetivo preliminar: el 95 % de las consultas principales responde en un máximo de 3 segundos con 100 usuarios concurrentes en el escenario de prueba definido, excluyendo interacción humana y carga de mapas externos. |
| AC05 | Disponibilidad | Los usuarios requieren consultar y gestionar citas durante el horario de operación. | Objetivo preliminar: disponibilidad mensual del 99,5 % para las funciones principales; medir autenticación y reservas e informar fallos de forma recuperable. Este objetivo depende también de los servicios contratados. |
| AC06 | Escalabilidad | Aumentan el número de barberías, usuarios y solicitudes de disponibilidad. | La capacidad puede ampliarse mediante recursos administrados, índices y optimización de consultas sin crear una aplicación o base independiente por barbería. Se verificarán límites del proveedor y cuellos de botella antes de escalar. |
| AC07 | Confiabilidad | El correo de una invitación falla después de registrar correctamente la operación principal. | El registro se conserva, se comunica el fallo de envío y puede reintentarse de forma controlada. La entrega de correo ocurre fuera de la transacción principal. El fallo del proveedor no revierte una operación ya confirmada; los avisos internos que formen parte de esa transacción conservan su atomicidad. |
| AC08 | Mantenibilidad y modificabilidad | Cambia una regla de reseñas, el proveedor de mapas o el almacenamiento de imágenes. | La regla se modifica en el módulo correspondiente y el cambio de proveedor se concentra en su adaptador. Dominio y casos de uso mantienen dependencias hacia el interior y pueden probarse sin interfaz ni servicios externos; se ejecutan pruebas de regresión de las funciones afectadas. |
| AC09 | Usabilidad y accesibilidad | Un cliente reserva desde una pantalla móvil pequeña, recibe un error de disponibilidad o consulta barberías en un mapa. | Los flujos presentan pasos claros, estados de carga, vacío y error; mantienen controles táctiles adecuados y mensajes comprensibles. La información de ubicación también puede consultarse en texto y ninguna acción depende únicamente del color. |
| AC10 | Preservación histórica | Cambian el nombre de un servicio, su precio o las políticas después de confirmar una cita. | La consulta histórica conserva las condiciones registradas para la reserva, sin reemplazarlas silenciosamente por la configuración actual. |

## Evaluación

Cada atributo se desarrolla con fuente, estímulo, artefacto, entorno, respuesta y medida en [escenarios de atributos de calidad](08-escenarios-atributos-calidad.md). Estos escenarios ya contemplan la autorización de pagos de AC01, la gestión de imágenes y reseñas de AC02, la confirmación concurrente de pagos de AC03 y la aplicación de Clean Architecture en AC08. Las metas de rendimiento y disponibilidad siguen pendientes de validación.

El atributo indica **qué cualidad se espera**; el escenario explica **cómo se comprobará**. Cada escenario incluye herramienta propuesta, procedimiento, evidencia y estado. Por ejemplo, AC04 exige tiempos adecuados y EQ-04 propone k6 para generar consultas simultáneas y comparar los tiempos con la meta.

Las herramientas se explican en el documento de escenarios. Las pruebas E2E recorren las pantallas como lo haría un usuario; las pruebas de integración comprueban la colaboración con el backend; las pruebas de carga aumentan las solicitudes; y el monitoreo observa el servicio durante un periodo. Se elige el método según el atributo. La evaluación con usuarios complementa la automatización para comprobar comprensión y facilidad de uso.

Este apartado define el plan de evaluación. Los resultados se incorporarán cuando se ejecuten las pruebas y se conserve la evidencia correspondiente.
